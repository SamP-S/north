# 051 — v1.0 polish: claim-surface completion + safety fixes

**Status:** accepted, in implementation
**Date:** 2026-07-12
**Origin:** post-050 review pass; all five items user-approved 2026-07-12.

## Summary

1. **Ready-but-assigned limbo warning.** `move X ready` keeps the assignee,
   making X invisible to `next`/`take` forever. `SetStatus` now returns an
   advisory warning when the target is `ready` and an assignee is set
   (stderr in human/plain, `"warnings"` in `--json`), telling the user to
   clear it with `edit --assignee ""`. Skill gets a matching recovery note.
   No doctor check — ready+assigned can be a legitimate human pre-assignment,
   so it must not read as a board *problem*.
2. **Commented `config.yml` scaffold.** `init` writes a commented template
   (same discoverability story as `~/.north/config.yml`) instead of bare
   marshaled YAML. Known caveat, documented in the template itself:
   `north config set` rewrites the file without comments.
3. **`north take <id>`.** Optional positional id: claim a *specific* task
   atomically. Strict semantics — refused (`conflict`) unless the task is
   active + `ready` + unassigned + deps met (each refusal names the reason;
   unknown id is `not_found`). No steal, no overrides. `max_wip` applies.
   `--label` cannot be combined with an id (`invalid`).
4. **`north next -l/--limit N`.** Show the next N workable tasks in take
   order. Limit 1 (default) keeps the existing `{"task": …|null}` contract;
   limit ≥ 2 renders as a list (`{"tasks": […]}` under `--json`, task-list
   rows otherwise). Limit < 1 is `invalid`.
5. **`cleanup` holds the lock for its whole run + `--dry-run`.** Previously
   Cleanup snapshotted unlocked and archived via per-task `SetState` (each
   re-locking), so a task un-done mid-run could still be archived. Now one
   `Lock()` spans snapshot + all archive writes (saving directly, like
   Delete's heal path). `--dry-run` lists what would be archived without
   locking or writing.
