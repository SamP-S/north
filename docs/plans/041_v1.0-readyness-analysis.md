# 041 — North v1.0 Readiness Analysis: Bugs, Gaps, and Roadmap


## Context

North is feature-complete as an MVP (two-axis board, CLI, TUI, skill) and the goal
is a focused, "bullet-proof" v1.0 that can be publicly released. This analysis is
based on: reading all of `docs/design/`, the README, every Go source file, running
the test suite, empirically exercising the built binary against crafted boards
(CRLF files, corrupt files, duplicate IDs, git worktrees, missing git identity),
and exhaustive feature inventories of the two inspiration projects (Backlog.md
v1.47 and kanban-md) from the local clones in `tmp/`.

**Audience assumption:** solo dev + AI agents, extended to "one human across
multiple machines/branches/worktrees" — i.e. small-team-via-git behavior matters,
enterprise does not.

Verification status: items marked **[confirmed]** were reproduced against the
built binary in a scratchpad board; the rest are from code reading.

---

## 1. Bugs (priority ordered)

### P0 — break the board or lose data

1. **One malformed task file breaks the entire board.** [confirmed]
   `tasks.List` (`internal/tasks/tasks.go:319`) aborts on the first file that
   fails to parse, so a single bad file makes `task list`, `board`, `cleanup`,
   the TUI, and even the delete-dependents scan fail. Worse, the error often
   doesn't name the file (`error: unknown status ""` — status/id validation
   errors in `loadTask` lack the filename prefix that read/yaml errors get).
   Fix: tolerant listing (skip + collect warnings, print to stderr / `"warnings"`
   in JSON), and include the filename in every parse error.

2. **CRLF line endings make a task unparseable.** [confirmed]
   `splitFrontmatter` (`tasks.go:123`) only accepts `---\n`. A task file saved on
   Windows, or checked out with `core.autocrlf=true`, parses as "no frontmatter"
   → `unknown status ""` → via bug #1, the whole board dies. You work across
   machines; this is a realistic v1.0 killer. Fix: normalize `\r\n` before
   splitting (and consider a `.gitattributes` written by `north init`).

3. **Unknown frontmatter keys are silently deleted on every write.**
   `render()` marshals the fixed `frontMeta` struct (`tasks.go:151`), so any key
   North doesn't know (`priority: high` added by hand, or by a future North
   version) is erased by the next `edit`/`move`/`promote`. For a tool whose pitch
   is "files are the source of truth, anything can read/write the board", this is
   silent data loss and also blocks forward-compatibility. Fix: round-trip
   unknown keys (parse into `map[string]any` or `yaml.Node`, overlay known fields).

4. **`auto_commit` in a linked git worktree silently commits nothing.** [confirmed]
   With `auto_commit: true` inside a `git worktree add` checkout, `north task
   create` exits 0, the file is left *staged*, and no commit exists on any
   branch. go-git's linked-worktree support is incomplete. You use worktrees
   daily. Related: **`auto_commit` with no git identity fails *after* the file
   write** [confirmed] — `error: author field is required`, exit 1, but the task
   *was* created; an agent will retry and create a duplicate. go-git also ignores
   commit signing, hooks, and `includeIf` config.
   Recommended fix: replace go-git with shelling out to the system `git` binary
   (only needed when `auto_commit: true`, i.e. only ever inside a git repo where
   `git` exists) with a clear error if unavailable. Bonus: removes ~40 indirect
   deps and shrinks the binary. Alternatively: keep go-git but detect linked
   worktrees and fail loudly, and default the author.

### P1 — wrong behavior, agent-hostile output

5. **Duplicate task IDs after a git merge are silently tolerated.** [confirmed]
   Two branches each create `task-13`; after merge both files exist. `list` shows
   both, `view`/`edit`/`move` operate on whichever file sorts first, `NextID`
   moves on. No detection, no repair. Needs `north doctor` (detect) and ideally
   kanban-md-style self-healing (renumber + report). Same family: the documented
   `NextID` race between parallel agents — an advisory lock file (`flock` on
   `north/.lock`) is cheap and fixes both parallel creates and read-modify-write
   races.

6. **`task delete --json`/`--plain` without `-y` pollutes machine output.** [confirmed]
   The interactive prompt `Delete task-1 (...)? [y/N] ` and `Aborted.` go to
   *stdout*, so the "stable, parseable" contract is broken. Fix: with `--json`/
   `--plain` or when stdin is not a TTY, refuse without `-y` (error to stderr);
   prompts should go to stderr regardless.

7. **`$EDITOR` with arguments breaks the TUI editor.**
   `exec.Command(editorFor(), path)` (`internal/tui/editor.go:145`) treats
   `EDITOR="code --wait"` or `emacsclient -t` as a single binary name. Fix: split
   the value (or run via `sh -c "$EDITOR \"$1\""`). Also: `$VISUAL` should take
   precedence over `$EDITOR` (convention), currently reversed (`editor.go:117`).

8. **TUI truncates titles by bytes, not runes/cells.**
   `title[:maxTitle]` with `len(title)` (`internal/tui/board.go:453-459`,
   `list.go:390-392`) slices UTF-8 mid-rune (garbled output) and miscounts wide
   chars (CJK/emoji misalign columns). Use `charmbracelet/x/ansi.Truncate` or
   runewidth — already in the dependency tree.

9. **Editor exiting non-zero is treated as "save".**
   `openEditor`'s callback ignores the error (`editor.go:146-152`) — `vim :cq`
   (the universal "abort") still applies changes. Treat non-zero exit as cancel.

### P2 — footguns and hygiene

10. **Nested `north init` silently creates a shadowing board.** [confirmed]
    Running `init` in a subdirectory of a project that already has a board
    creates a second board that hijacks discovery for that subtree. **Decision:**
    refuse outright — `error: north already initialised (found board at <path>)` —
    no `--force` escape hatch needed for v1.0.
11. **Non-atomic writes.** `os.WriteFile` in place; an interrupt can truncate a
    task file. Write temp + `os.Rename` (same dir).
12. **Malformed `config.yml` is silently ignored** (`board.go:127`) — a YAML typo
    silently turns `auto_commit` off. At minimum warn on stderr.
13. **`go.mod` is stale**: bubbletea/bubbles/lipgloss/glamour are direct imports
    but tagged `// indirect`. Run `go mod tidy`.
14. **`selectByID` only searches the filtered list** (`list.go:512`) — Enter on a
    board card while a list filter is active silently does nothing.
15. **Body is `TrimSpace`d on load and save** — intentional leading/trailing
    whitespace in bodies (rare, but e.g. a body starting with an indented code
    block) is altered on round-trip.
16. **No LICENSE file** in the repo. Not a code bug, but a hard blocker for
    public release. **Decision:** MIT (was GPL-3.0; changed 2026-07-05). No CHANGELOG — intentional, not tracked.

## 2. Refactoring / architecture

Ordered by leverage:

1. **A board snapshot type.** `north board` scans and parses every file three
   times (`StatusCounts` + 2×`StateCount`); TUI `loadData` similar; `find` scans
   for every op. Introduce `board.Load() (*Snapshot, []Warning, error)` that
   parses everything once (tolerantly — fixes bug #1 structurally) and derives
   lists/counts/lookups from it. Mutations keep operating per-file.
2. **Frontmatter round-tripping** (bug #3) belongs in one place — a small
   `frontmatter.go` that parses to `yaml.Node`/map, overlays typed fields, and
   preserves unknown keys and key order.
3. **Replace go-git with `exec git`** (bug #4). `internal/git` keeps its tiny
   interface (`CommitBoard`); implementation becomes ~30 lines of `git add`/
   `git commit` with `-c user.name=north` fallbacks. Cuts the dependency tree
   roughly in half.
4. **Unify the TUI's duplicated modal logic.** `boardModel` and `listModel` each
   implement their own status picker (`board.go:316`, `list.go:249` — near-identical)
   and two *different* confirm mechanisms (modal overlay vs inline lines with a
   `pendingFn` closure, which also runs synchronously inside `Update`,
   `list.go:126-146`, unlike the board's async `tea.Cmd`). Extract one shared
   modal/confirm component owned by the root `Model`.
5. **CLI run-context helper.** Every RunE repeats `LocateBoard("") → op → render
   → print`. A `withBoard(func(ctx) error)` wrapper (or cobra `PersistentPreRunE`)
   removes ~15 copies and gives one place to add a future `-C/--dir` flag.
6. **Error model**: `errors.As` in `internal/errors` uses a direct type assertion;
   use stdlib `errors.As` so wrapped errors (`fmt.Errorf("...: %w", err)`) still
   map to exit behavior. Consider `%w` wrapping throughout.
7. **`tasks.Edit`'s 6-pointer signature** → an `EditOpts` struct with optional
   fields; the TUI's forced non-nil pointers (`model.go:190` always overwrites
   agent/labels/deps even if the user only changed the title) becomes clearer.
8. **Injectable clock** (`now func() time.Time`) as kanban-md does — makes
   `cleanup --older-than` and timestamp tests deterministic.
9. **Testing gaps**: no e2e test that runs the compiled binary; no TUI golden/
   snapshot tests (kanban-md's `View()` snapshots with `-update` flag are worth
   copying); no fixture-based backward-compat tests for the file format. The
   design doc's testing section should grow these.

## 3. Missing expected features (functionality users will assume exists)

Priority ordered; all fit current constraints:

1. **`north doctor`** — validate the whole board: duplicate IDs, unparseable
   files (with filenames), dangling `depends_on`, dependency cycles, ID/filename
   mismatches, CRLF files. Optional `--fix` (renumber duplicates, rewrite CRLF).
   Already sketched in `99_roadmap.md`; the confirmed bugs above make it a v1.0
   requirement, not a nice-to-have.
2. ~~`priority` field~~ — **deferred to roadmap (§8)**, not v1.0 scope.
3. **Append to body**: `task edit --append-body` (and `--body-file` on edit,
   already noted as a design inconsistency). Agents logging progress currently
   must read-modify-replace the whole body — racy and token-expensive. This is
   the biggest agent-ergonomics gap.
4. **Search/filtering**: `task list --search <substr>` (title+body+labels) and
   `--label`, `--agent` filters. Today agents must pull everything and grep.
5. **ID format**: replace `task-<n>` with plain `<n>` everywhere — the `task-`
   prefix is redundant (North only has one object type) and adds no value.
   See the full decision in §11.
6. **`north task next` (or `pick`)** — print the highest-priority `ready` active
   task whose `depends_on` are all done/archived. Turns the skill's "figure out
   what to do" into one call. (Claiming/locking for parallel agents is roadmap.)
7. **`north config get|set <key>`** — currently the only way to enable
   `auto_commit` is hand-editing YAML, which bug #12 makes hazardous.
8. **Batch operations**: comma/space-separated IDs for `move`, `archive`,
   `promote`, `delete` (kanban-md pattern, exits 1 if any fail).
9. ~~Board export~~ — **rejected**: the user can already pipe `north task list --json`
   (or `--plain`) to a file themselves; a dedicated export command adds surface
   for no real gain.
10. **Statistics**: `north stats` — counts, completion %, average age, stale
    tasks, blocked-by-deps. Cheap to derive from the snapshot type.

## 4. Missing / non-standard CLI behavior

1. **Machine-readable errors**: with `--json`, errors should be emitted as JSON
   (`{"error": {"code": "conflict", "message": ...}}`) on stderr or stdout;
   today agents get a text line. The `code` field already exists internally.
2. **Distinct exit codes** (optional but cheap): 1 generic, 2 usage, 3 not-found,
   4 conflict — document them in the skill so agents can branch without parsing.
3. **`-C <dir>` / `--dir` global flag** to operate on a board outside cwd
   (standard in git/make/kanban-md; helps scripts and multi-repo setups).
4. **Prompts to stderr + TTY detection** (bug #6).
5. **`north completion`** exists (cobra default) [confirmed] but is undocumented —
   add to README/docs; consider `north completion install`.
6. **`NO_COLOR`** honored implicitly by lipgloss, but an explicit `NORTH_FORMAT=
   plain|json` env default (kanban-md's `KANBAN_OUTPUT`) is handy for agent
   shells.
7. **`init` output**: says "Initialized" even when the board already existed —
   distinguish "already exists". Consider `init` printing next-steps hint
   (`north skill install`, `north task create ...`).
8. **stdin body**: `--body-file -` reads stdin — standard idiom, trivially cheap,
   great for heredocs (Backlog.md has documented agent pain here).
9. **Naming notes**: `task move <id> <status>` is defensible (status = column =
   kanban "move") but it's the one command name agents most often guess wrong
   against peers (`edit --status`, `set-status`). Keep `move`, but consider
   accepting `north task move <id> --to <status>` and/or documenting hard in the
   skill. `cleanup` might grow `--dry-run`.

## 5. Skill improvements (`internal/skill/skill/SKILL.md`)

The skill is accurate but reference-shaped; agents do better with workflows:

1. **Add a "typical loop" section** — the single highest-value change:
   ```
   north task list --status ready --plain   # what can I do?
   north task view task-12 --json           # read the full brief
   north task move task-12 in_progress
   …do the work…
   north task edit task-12 --body-file notes.md   # record results
   north task move task-12 done
   ```
   and a matching "when you finish/fail/get stuck" mapping to `done|failed|blocked`
   with one-line semantics for each status (currently the skill never says what
   `failed` vs `blocked` *mean*).
2. **Warn that `edit --body` REPLACES the body** and show the safe
   read-modify-write pattern (until `--append-body` ships — then teach that).
3. **Quoting/multi-line guidance**: recommend `--body-file` (or stdin) for
   anything multi-line; Backlog.md found agents mangle `\n` in `--body` strings
   badly enough to document it.
4. **State the error contract**: `error: <message>` on stderr, exit ≠ 0; with
   `--json`, parse stdout only.
5. **Drop or soften "Always start by running `north board`"** — for a specific
   request ("mark task-3 done") that's a wasted call; say "run `north board`
   when you need an overview or are unsure the board exists".
6. **Trim duplication**: the "uniform `--plain|--json`" paragraph appears twice;
   the command list in "Rules for agents" repeats the earlier section. Shorter
   skill = fewer tokens per activation.
7. **`north skill check`** command (kanban-md has it): compare the stamped
   `<!-- north-skill-version -->` against the binary and tell the user to
   re-run `install`. The version stamp already exists; nothing reads it.
8. **Mention dependency semantics**: `depends_on` is an ordering hint; suggest
   agents check dependencies are `done` before starting a task (or point at
   `task next` once it exists).

## 6. TUI UX improvements

1. **Auto-reload on file change** (fsnotify) or at least an `r` refresh key —
   the board goes stale the moment an agent mutates a task, which is the primary
   use case (human watches TUI while agent works). kanban-md treats this as
   table stakes.
2. ~~Show drafts/archive on the board view~~ — **rejected**: switching to list
   view already shows them; no need for extra keys/columns to duplicate that.
3. **Status picker: grey out illegal transitions** (and the current status)
   instead of letting Enter produce an error banner (`board.go:328`).
4. **Detail pane omits `id` and `depends_on`** (`list.go:433-450`) — the two
   fields you most need for cross-referencing. Add them (and render deps as
   `task-4 (done)` with status).
5. **Column overflow**: board columns have no scrolling — with more tasks than
   rows the column renders past its box. Needs per-column windowing like the
   list's offset logic.
6. **Search should match ID and labels**, not just title (`list.go:487`);
   kanban-md's `#12` id-prefix idiom is nice.
7. **`q` while help is open should close help** (parallel with esc), not quit.
8. **List navigation**: `g/G` (top/bottom), page-up/down; Enter in the list pane
   could focus detail (currently only `l`/`→`).
9. **Esc from list view could return to board** (Enter on board → list is
   one-way; tab is the only way back).
10. **Card richness**: show labels and kanban-md-style age-in-status coloring;
    a `created_at`-based dim for stale `ready` tasks. (No priority — deferred.)
11. **Editor template**: consider editing real task-file format (YAML frontmatter
    + body) instead of the bespoke `# title / agent: / labels:` header — one
    format to learn, and the parser (`ParseEditorResult`) has edge cases (body
    lines swallowed if the blank separator line is deleted; literal title
    `"Task title here"` treated as abort).
12. **Mouse/wheel scroll** in list & detail panes (bubbletea supports it cheaply).
13. **Empty-board onboarding**: a fresh board shows five `(empty)` columns; a
    one-line hint ("press c to create your first task") helps.

## 7. Minor improvements

- Include the offending filename in *all* task parse errors (part of bug #1).
- `north --version` / `version` already fine; Makefile stamps git describe — good.
- `make build` isn't reproducible-release-ready: add goreleaser (or a dist
  target) with linux/darwin/windows × amd64/arm64 for v1.0.
- CI: GitHub Actions running `make vet test` on PR + release workflow. None exists.
- README: add completion docs, a demo GIF (vhs tape like kanban-md), badges,
  install-from-release instructions, LICENSE.
- `north init` could offer to add `north/` guidance to `.gitattributes`
  (`north/**/*.md text eol=lf`) to prevent bug #2 at the source.
- Delete stale `bin/` from repo if committed; confirm `north/` (dogfood board)
  is intentional in-repo.
- Board command human output could show a mini bar (`ready ████ 4`) — pure polish.
- Doc comments are strong; keep the standard.

## 9. Recommended v1.0 cut (opinionated, revised after review)

**Must (release blockers):** bugs 1–16, including: tolerant listing + filenames in
parse errors; CRLF normalization; frontmatter round-tripping (done properly, not
patched — §2.2); exec-git replacing go-git for `auto_commit` (§2.3); nested-`init`
refusal ("north already initialised"); prompts/`-y` contract; `go mod tidy`;
GPL-3.0 LICENSE. `north doctor` promoted to Must given the confirmed duplicate-ID
and corrupt-file failure modes.

**Should (v1.0 quality):** `--append-body` + `edit --body-file`; list
`--search`/`--label`; bare-number ID shorthand (§11 below); `north config
get/set`; skill rewrite (workflow loop + body-replace warning + `skill check`);
TUI refresh key + truncation fix + detail-pane id/deps + picker legality + real
task-file-format editor template (§11 below).

**Defer to roadmap (§8, not touched this pass):** priority field, board export,
claims/pick/agent-name, stats/log/context, sequences, AC checklists, configurable
statuses, TUI drafts/archive-on-board-view.

## 10. Process

Per user direction: this analysis is not being split into numbered follow-up
plans (042/043/044/045). Instead, one consolidated implementation plan covering

(Fable) to execute end to end. §8 (roadmap) stays as a reference list only — not
scoped for this pass.

## 11. Open design questions (resolved during review — 2026-07-03)

- **Status transition guardrails**: **decided — removed, made freeform**,
  consistent with the state-move decision below. `north task move <id>
  <status>` allows any status → any other status in one call (e.g. `ready →
  failed` directly, no need to pass through `in_progress`). `models.Transitions`
  becomes permissive (any→any) rather than the current graph; the fixed
  status *list* (`ready/in_progress/done/failed/blocked`) is unchanged, only the
  edges between them are dropped. Still active-tasks-only (state gates
  status, unchanged). Update skill wording accordingly — it should no longer
  describe a required path through the statuses.
- **promote/demote/archive/restore → single state-move verb**: **decided —
  collapse into one `north task state <id> <state>` command** (`draft|active
  |archive`), replacing the four separate verbs. **Fully freeform** (revised
  2026-07-04): `models.StateTransitions` is deleted — any state → any other
  state in one call, including archive→active directly. In the TUI the `p` and
  `a` keys are removed, replaced by a single `s` key opening a 3-item state
  picker modal, mirroring the `m` status picker (`m` = status, `s` = state).
- **ID format**: **decided — replace `task-<n>` with plain `<n>` everywhere**,
  superseding the earlier "keep `task-12` canonical, accept bare shorthand"
  recommendation. The `task-` prefix serves no purpose once there's only one
  object type on the board; it's a pre-v1.0 project with no installed base, so
  no migration/back-compat path is needed — just change the format outright.
  Concretely (all in scope for the implementation plan):
  - `board.NextID` returns e.g. `"12"` instead of `"task-12"`.
  - Filenames become `<n>-<slug>.md` (e.g. `12-add-login.md`) instead of
    `task-<n>-<slug>.md`; `board.idRe` (`^task-(\d+)`) becomes `^(\d+)-`.
  - Frontmatter `id:` field stores the bare number (as a string, to avoid YAML
    coercing it to an int and stripping meaning).
  - `depends_on` lists become `["4"]` instead of `["task-4"]`.
  - Every CLI example, the skill (`SKILL.md`), design docs (`02_board-data-model.md`,
    `03_cli.md`), README, and tests referencing `task-N` throughout this
    analysis and the codebase update to bare `N`. (This analysis document's own
    examples above still say `task-12` etc. — read those as illustrative,
    written before this decision; the implementation plan should not carry the
    prefix forward.)
- **Editor template**: switch the TUI's `c`/`e` editor template from the bespoke
  `# title / agent: / labels:` header format to the real on-disk task file
  format (YAML frontmatter + body), reusing the existing frontmatter
  parser/renderer instead of `ParseEditorResult`'s hand-rolled parser.
