# 058 — v1.0 robustness & CLI-consistency fixes

## Summary

Implements the fixes for audit plan [057](057_v1.0-robustness-audit.md), items A1–A8 and B9–B14. Initially held, now decided [2026-07-18]:

- **B15**: alias `--label` and `--labels` per command (cobra flag-normalize), so either spelling works everywhere — set semantics on create/edit, filter semantics on list/next/take. Canonical names in docs stay as today.
- **B16**: aborted interactive delete exits **1** (plain error, not conflict); exit-code contract text amended to "1 = internal or aborted".
- **B17**: keep the `unknown command` string-prefix detection, add a comment noting it is pinned by a CLI exit-code test (a cobra rewording breaks loudly in CI).

## Scope

### A. Robustness

- **A1 `config set`**: take `board.Lock` before load/write; replace the plain `WriteConfig` call with a comment/unknown-key-preserving yaml.Node round-trip (generalise `setConfigLastID` into a shared `setConfigKey` helper) so a concurrent `last_id` bump and user comments both survive.
- **A2 `auto_commit` parsing**: `LoadConfig` rejects non-boolean `auto_commit` values with `Invalid` instead of silently falling back.
- **A3 lock steal**: steal stale locks by `os.Rename` to a temp name then remove — rename is atomic so only one stealer wins; losers keep retrying. Never remove a lock we didn't win.
- **A4 `skill install` exit code**: only unknown `--target` names are `Invalid`; mkdir/write failures pass through as internal (exit 1).
- **A5 `take` config read**: load config after acquiring the board lock in `tasks.Take`.
- **A6 batch delete**: `tasks.Delete` returns the removed task (`*models.Task, []string, error`); the CLI drops its pre-`Get` in single and batch paths — one lock hold and one snapshot load per id.
- **A7 `batchReport`**: propagate plain-mode render errors instead of silently dropping them.
- **A8 normalisation**: trim assignee; trim labels and drop empties in `Create`/`Edit`/`Take` and the CLI `--label` filters, so stored and filtered values agree.

### B. CLI consistency

- **B9 `--json`/`--plain` coverage**: add output flags to `config list|get|set`, `skill check`, `version`.
  Payloads: `config list` → `{"config": {…typed values…}}`; `config get`/`set` → `{"key": …, "value": …}`; `skill check` → `{"targets": [{"agent", "path", "installed", "binary", "status"}]}` (status: `ok|outdated|missing`); `version` → `{"version": "…"}`. Plain stays terse text. `skill install`/`show` remain human-only.
- **B10 `task view` envelope**: `--json` wraps as `{"task": …, "warnings": []}` — identical shape to every mutation payload.
- **B11 `next -l 0`**: 0 = all (library already supports it); only negatives rejected; help/Long text updated to match `list`.
- **B12 inactive note**: the draft/archive advisory from `move`/`state` rides the op's `warnings` (JSON payload included) instead of a bare stderr print; `noteInactive` removed.
- **B13 `cleanup` warnings**: `tasks.Cleanup` returns snapshot warnings; CLI prints them on stderr (human/plain) and `render.CleanupReport` carries the real list under `--json`.
- **B14 `north tui`**: rejects positional args (`Args: noArgs`).

Docs: update `internal/skill/skill/SKILL.md` and `README.md` where the surface changed (B9–B13).
