# 057 — v1.0 robustness & CLI-consistency audit

## Summary

Full read of every package (`cmd/north`, `internal/{cli,tasks,board,models,render,git,errors,skill,tui,version}`) plus behavioural probes against the built binary on a scratch board. Build, `go vet`, and the full test suite pass. Findings below are ordered by severity; each was reproduced, not just read. Nothing here is implemented yet — this plan is the list to burn down before tagging v1.0.

## Findings

### A. Robustness

1. **`config set` races id allocation and destroys config content.** `newConfigSetCmd` writes via `board.WriteConfig` without taking the board lock. (a) A concurrent `task create` bumps `last_id` through `setConfigLastID`; `config set` then writes back its stale in-memory `LastID`, rewinding the high-water mark → a deleted task's id can be reissued. (b) `WriteConfig` re-marshals the struct plain, so user comments **and unknown keys** are dropped (verified: an added `custom_key` vanished), while `setConfigLastID` carefully round-trips the yaml.Node to preserve both. Fix: take `board.Lock` in `config set`, and write through a node round-trip like `setConfigLastID` (one shared helper).

2. **`auto_commit` typo is silently ignored.** `LoadConfig` hard-errors on malformed `deps_enforcement`/`max_wip`, but `toBool` falls back silently: `auto_commit: flase` → `false` (verified). The package comment explicitly says a silently ignored typo must not silently change behaviour — this is exactly that case. Fix: reject non-boolean `auto_commit` like the other keys.

3. **Lock-steal race in `board.Lock`.** Two waiters can both stat the same stale `.lock`; A removes and recreates it, then B's `os.Remove` deletes A's *fresh* lock → two concurrent writers. Small window, but the whole point of the lock is the id-allocation window. Fix options: re-stat and compare mtime/inode before removing, or steal via `os.Rename` of the stale file so only one stealer wins.

4. **`skill install` maps I/O failures to exit 2 (invalid).** `newSkillInstallCmd` wraps every error in `nerrors.Invalid` — a permission-denied mkdir exits 2 instead of 1 (verified). Only unknown `--target` names are genuinely invalid; let other errors pass through as internal.

5. **`take` reads `max_wip` before acquiring the lock** (`tasks.Take` loads config, then locks). A `config set max_wip` landing in between is enforced stale. One-line reorder.

6. **Batch `task delete` is non-atomic per id and double-loads.** The CLI does `tasks.Get` then `tasks.Delete` — two separate snapshot loads and lock holds per id; the reported task can differ from what was deleted. Consider `Delete` returning the removed task so the pre-read disappears.

7. **`batchReport` swallows plain-mode render errors** (`if out, err := …; err == nil` drops the error silently). Return it like the JSON branch does.

8. **Assignee/labels are stored untrimmed.** `--assignee " bob "` is saved raw; `take`'s max_wip match is case-insensitive but not whitespace-insensitive, and cobra's `StringSlice` keeps spaces after commas in `--labels "a, b"` → label `" b"` never matches `--label b`. Normalize (trim) on create/edit/take.

### B. CLI consistency (breaking changes are cheap only until v1.0)

9. **`--json`/`--plain` missing from `config list|get|set`, `skill install|check|show`, and `version`** (verified: `config get max_wip --json` → unknown flag). Every other command has both; agents reading config must scrape text. At minimum `config get/list` and `skill check` should speak JSON.

10. **Inconsistent JSON envelope for a single task.** `task view --json` prints a bare task object; every mutation prints `{"task": …, "warnings": […]}`; lists print `{"tasks": …, "warnings": […]}` (verified). Unify — wrap `view` in the same `{"task": …}` envelope now, while breaking is still allowed.

11. **`-l/--limit` means different things on `list` vs `next`.** `task list -l 0` = unlimited (default 0); `next -l 0` = error, default 1, and there is no way to ask for "all" even though `tasks.Next` supports `limit <= 0` = all. Align: accept 0 = all on `next`.

12. **`noteInactive` prints to stderr even under `--json`.** `task move`/`state` on a draft emits `note: 1 is draft; …` on stderr while the payload's `warnings` array stays empty (verified). Machine consumers should get it in `warnings`; it is advisory, same as the ready-assignee warning that already rides the payload.

13. **`cleanup` never surfaces snapshot warnings.** Human/plain print nothing and the JSON payload hardcodes `"warnings": []`, unlike list/board/next/take — a malformed done-task file is silently excluded from archiving with no signal. Thread `snap.Warnings` through `tasks.Cleanup`.

14. **`north tui` accepts positional args** (`north tui bogus` runs; every sibling declares `Args`). Add `Args: noArgs`.

15. **`--label` (filter) vs `--labels` (replace)** — deliberate filter/set distinction, but a one-character trap on an agent-driven CLI. Decide once for v1.0: either keep and document loudly in SKILL.md, or rename the filter to `--with-label`. (Decision item, not a bug.)

16. **Aborted interactive delete exits 4 (conflict).** `errAborted = nerrors.Conflict("aborted")` — a user pressing "n" gets the same exit code as a real conflict. Convention elsewhere is 1 or 130. (Decision item; if kept, document in the exit-code contract.)

17. **`Execute` sniffs `unknown command` by string prefix** on cobra's error text — brittle across cobra upgrades. Consider `cmd.Find`-based detection or accepting exit 1. (Low.)

### C. Non-issues checked and cleared

- `next`/`take` TOCTOU: correctly closed by single-lock `Take`; comments defend it.
- Frontmatter round-trip preserves unknown keys/order; id path-escape guarded by `taskIDRe`.
- `doctor` exit-0-with-issues is documented as intentional; `--json` carries the findings.
- Snapshot tolerance, duplicate-id handling, cycle detection, CRLF handling: sound, well-tested.
- TUI: no mouse, modal ownership in root model, OSC 52 yank, editor flow — all consistent; themes are colors-only as required.
- Docs/SKILL.md spot-checked against the current flag surface — no drift found.
