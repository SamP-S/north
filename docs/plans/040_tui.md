# Plan 040: TUI (`north tui`)

## Context

North has a full CLI but no interactive interface. Users want a terminal UI that mirrors backlog.md's UX: a kanban board view, a task list+detail view, tab-switching between them, and external-editor-based create/edit. The TUI is a new `north tui` entry point; existing CLI commands remain unchanged.

---

## Library choices

| Package | Role |
|---|---|
| `github.com/charmbracelet/bubbletea` | Event loop / Elm-architecture model |
| `github.com/charmbracelet/lipgloss` | Layout, borders, colors |
| `github.com/charmbracelet/bubbles` | `viewport` (scrollable pane), `textinput` (search) |

Glamour (markdown rendering) is **deferred** — body shown as plain text initially to keep deps at 3.

---

## Architecture

Single root `tea.Model` (`internal/tui/model.go`) owns a `viewMode` enum and delegates to two sub-models:

- **Board model** (`board.go`) — kanban columns by status for active tasks; draft/archive counts in footer
- **List model** (`list.go`) — left pane (task list, all states) + right pane (task detail via `bubbles/viewport`)

Both sub-models implement `tea.Model`. The root model routes `tea.Msg` to the active sub-model and handles tab-switching.

### External editor flow
`tea.ExecProcess(cmd, func(err error) tea.Msg {...})` suspends the TUI, opens `$EDITOR` on a temp file, then resumes. Used for both create (template) and edit (pre-populated).

**Create template:**
```
# Task title here

Body text here.
```
Title = first `# ` line; body = everything after. Labels parsed from a `labels:` line if present.

## Views

### Board view (default)
- Horizontal columns: `ready | in_progress | done | failed | blocked`
- Column header: status name + task count
- Task cards: ID (dimmed) + title; active card highlighted border
- Footer: `drafts: N  archive: N`
- Navigation: `h`/`l` columns, `j`/`k` tasks within column

### List + detail view
- Left 35%: scrollable task list (all states by default, filterable)
- Right 65%: selected task fields + body (scrollable via `bubbles/viewport`)
- Navigation: `Tab` / `←`/`→` to switch panes, `j`/`k` to scroll

### Shared keybindings
| Key | Action |
|---|---|
| `Tab` | Switch board ↔ list |
| `e` | Edit selected task in `$EDITOR` |
| `c` | Create new task in `$EDITOR` |
| `m` | Move status (picker modal, active tasks only) |
| `p` | Promote draft→active (or demote if active) |
| `a` | Archive task (with `y/n` confirm) |
| `d` | Delete task (with `y/n` confirm) |
| `r` | Restore archive→active |
| `/` | Live search/filter by title |
| `Esc` | Close modal / clear search |
| `?` | Help overlay |
| `q` / `Ctrl+C` | Quit |

## Deviations from original plan

- **`r` restore key removed** — `a` is context-sensitive: archives draft/active tasks, restores archived ones (mirrors `p` promote/demote pattern).
- **`restore` lands in `drafts/`** — changed from `archive → active` to `archive → draft` so humans review before re-activating. This is a breaking change also applied to the tasks package and `StateTransitions`.
- **List sorted by descending ID** — newest task first, ignoring state grouping.
- **Agent field in editor template** — `agent:` header added alongside `labels:` so both are editable via `$EDITOR`.
- **`Enter` on board card** — jumps to list view with that task focused in the detail pane.
- **Action keys work from detail pane** — `updateDetailPane` falls through to `updateListPane` for all non-scroll keys.
- **boardDataMsg routed at root** — fix for ready tasks not appearing on board when reloaded from list view.
